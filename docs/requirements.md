# SoraSense 要件定義書

## 2. システム概要

SoraSenseは、室内に設置したセンサーデバイスから温度・湿度の環境データを継続的に取得・蓄積し、利用者による現在値や履歴の確認を可能にするIoT環境モニタリングシステムである。

さらに、AI Agentが蓄積された実データを許可された範囲で参照し、利用者からの自然言語による質問に対して、集計・比較・異常傾向の説明を行う。

## 3. 背景と目的

### 3.1 背景

温度や湿度などの環境データは、取得・保存するだけでは状況の把握や改善判断に活用しにくい。利用者がデータを容易に確認でき、専門的な検索操作を行わなくても、自然言語で必要な情報を調査できる仕組みが求められる。

### 3.2 目的

- 室内の環境データを継続的に収集し、履歴として保存する。
- 現在および過去の環境状態を利用者が確認できるようにする。
- 設定された条件に基づいて環境異常を検知し、記録する。
- AI Agentを通じて、自然言語によるデータの照会、集計、比較および傾向把握を可能にする。
- センサーデバイスによる取得から利用者への情報提供まで、一連の流れを実用的なシステムとして成立させる。

## 4. 対象利用者

| 利用者 | 利用目的 |
|---|---|
| 一般利用者 | 室内環境の現在値・履歴・異常状況を確認し、AI Agentへ質問する |
| システム管理者 | デバイスやシステムの稼働状況を確認する |
| 開発・運用担当者 | デバイスや監視条件を管理する |

初期リリースでは、1人の利用者による利用を想定する。

## 5. 対象範囲

### 5.1 対象範囲内

- センサーデバイスによる環境データの取得
- センサーデバイスからの環境データの送信および受信
- 受信データの検証および保存
- 現在値、履歴および集計結果の提供
- 閾値に基づく異常の検知および履歴保存
- AI Agentによる自然言語でのデータ照会および分析
- デバイスおよびシステムの稼働状況確認
- 開発者が同等の実行環境を再現できること

### 5.2 対象範囲外

- 空調機器や家電の自動制御
- 医療、生命維持または防災用途における安全保証
- 測定機器としての公的な精度保証
- 大規模施設や多数拠点を対象とした運用
- AI Agentによるデータの自動削除・変更
- SMS、電話、外部チャットサービス等への通知連携
- 課金、契約および決済機能

### 5.3 将来候補

以下は将来の検討候補であり、初期リリースの要件および受入対象には含めない。

- 30日分データを用いた正式な性能受入試験
- 日次暗号化バックアップ、世代管理、隔離環境への定期復元
- CI、依存関係・コンテナイメージの自動脆弱性検査
- 本番専用Secret機構、包括的な障害・復旧試験
- 複数のセンサーデバイスおよび複数拠点への対応
- 温度・湿度以外のセンサー種別の利用
- 複数利用者、権限管理および認証の統合
- 外部サービスへの異常通知

## 6. 前提条件・制約

- AI AgentはGemini Developer APIのFree Tierを使用する。これは利用者が指定した必須の技術・費用制約である。
- 利用者または運用者は、課金を有効化していないFree Tierプロジェクトの有効なGemini APIキーを用意する。
- Free Tierの上限到達時はAI Agentを利用不能として扱い、有料枠へ自動的に切り替えない。
- Free Tierでは、Geminiへ送信した質問と回答生成に必要なデータがGoogleの製品改善に利用される場合がある。
- インターネット接続やGemini Developer APIの状態により、AI Agent機能を利用できない場合がある。
- AI Agentの回答は補助情報として扱い、重要な判断では元データを確認できることを前提とする。

## 7. 機能要件

### 7.1 デバイス・データ収集

| ID | 要件 |
|---|---|
| FR-001 | システムは、センサーデバイスで温度および湿度を取得できること。 |
| FR-002 | センサーデバイスは、温度および湿度を1分間隔で取得し、システムへ送信できること。 |
| FR-003 | 送信データには、デバイスを識別する情報および測定日時を含められること。 |
| FR-004 | システムは、センサーデバイスから送信された環境データを受信できること。 |
| FR-005 | 通信が一時的に失敗した場合、センサーデバイスは以降のデータ送信を継続できること。 |

### 7.2 データ管理

| ID | 要件 |
|---|---|
| FR-010 | システムは、受信した環境データの形式と必須項目を検証できること。 |
| FR-011 | システムは、正常な環境データを履歴として保存できること。 |
| FR-012 | システムは、不正なデータを正常データとして保存しないこと。 |
| FR-013 | システムは、指定期間の環境データを取得できること。 |
| FR-014 | システムは、最新の環境データを取得できること。 |
| FR-015 | システムは、指定期間について温度および湿度の最小値、最大値、平均値を提供できること。 |
| FR-016 | システムは、デバイス単位で環境データを識別できること。 |

### 7.3 環境状態の確認

| ID | 要件 |
|---|---|
| FR-020 | 利用者は、最新の温度、湿度および測定日時を確認できること。 |
| FR-021 | 利用者は、指定期間の温度および湿度の履歴を確認できること。 |
| FR-022 | 利用者は、日単位などの期間で集計された環境データを確認できること。 |
| FR-023 | 利用者は、データが最後に受信された時刻を確認できること。 |

### 7.4 異常検知・アラート管理

| ID | 要件 |
|---|---|
| FR-030 | システムは、設定された温度および湿度の閾値に基づいて異常を判定できること。 |
| FR-031 | システムは、検知した異常の内容、発生日時、対象デバイスおよび関連する測定値を保存できること。 |
| FR-032 | 利用者は、異常履歴を確認できること。 |
| FR-033 | 開発・運用担当者は、異常判定に用いる閾値を変更できること。初期リリースでは利用者向けの変更機能を提供しない。 |
| FR-034 | 同一デバイス、同一測定項目および同一異常方向の状態が継続している間は、未解消のアラートを重複して記録しないこと。正常範囲へ復帰した後に再発した場合は、新たなアラートとして記録すること。 |

### 7.5 AI Agent

| ID | 要件 |
|---|---|
| FR-040 | 利用者は、環境データに関する質問を自然言語で入力できること。 |
| FR-041 | AI Agentは、質問への回答に必要な場合、許可された範囲で保存済みデータを取得できること。 |
| FR-042 | AI Agentは、現在値、指定期間の履歴、統計情報および異常履歴に関する質問へ回答できること。 |
| FR-043 | AI Agentは、異なる期間の環境データを比較できること。 |
| FR-044 | AI Agentは、取得したデータに基づいて傾向や異常の可能性を説明できること。 |
| FR-045 | AI Agentは、取得できない情報を事実として推測せず、回答不能または情報不足であることを示すこと。 |
| FR-046 | AI Agentの回答から、回答の根拠となった対象期間および主要な測定値を確認できること。 |
| FR-047 | AI Agentは、環境データおよびアラート情報を参照専用で利用し、データを変更または削除しないこと。 |
| FR-048 | 外部AIサービスを利用できない場合でも、データ収集、保存および通常のデータ確認機能は継続できること。 |

### 7.6 デバイス・システム状態

| ID | 要件 |
|---|---|
| FR-050 | システムは、登録されたデバイスを識別し、その最終データ受信時刻を保持できること。 |
| FR-051 | 利用者は、最終データ受信時刻に基づくデバイスの稼働状況を確認できること。 |
| FR-052 | システム管理者は、測定データを受け付ける機能とデータ保存先が利用可能かを確認できること。 |

### 7.7 利用者インターフェース

| ID | 要件 |
|---|---|
| FR-060 | 利用者は、現在値、履歴、集計、異常履歴およびデバイス状態を閲覧用インターフェースで確認できること。 |
| FR-061 | 利用者は、簡易なAIチャットインターフェースでAI Agentへの質問と回答確認を行えること。各質問は独立して扱い、過去の質問・回答を前提としないこと。 |
| FR-062 | 閲覧用インターフェースおよびAIチャットインターフェースは、相互に移動できること。 |
| FR-063 | 初期リリースでは、デバイスおよび監視条件を変更する画面を提供しないこと。 |

## 8. 非機能要件

### 8.1 性能

| ID | 要件 |
|---|---|
| NFR-002 | AI Agentを利用しない要求は、外部AIサービスの応答状態に影響されないこと。 |
| NFR-003 | 初期リリースでは、1台のセンサーデバイスから1分間隔で24時間連続して送信されるデータを、欠損や重複を発生させずに処理できること。ただし、通信障害等によりシステムへ到達しなかったデータを除く。 |

### 8.2 可用性・継続性

| ID | 要件 |
|---|---|
| NFR-010 | 測定データを受け付ける機能またはデータ保存先に一時的な障害が発生しても、復旧後に再起動または再接続によって運用を再開でき、障害前に保存済みのデータを失わないこと。 |
| NFR-011 | 外部AIサービスの障害が、環境データの収集および保存を停止させないこと。 |

### 8.3 セキュリティ

| ID | 要件 |
|---|---|
| NFR-020 | APIキー、データベース認証情報およびその他の秘密情報をソースコードへ直接記載しないこと。 |
| NFR-021 | 管理機能は、許可された利用者だけが実行できること。 |
| NFR-022 | 外部から受け取るデータおよび利用者入力を検証すること。 |
| NFR-023 | AI Agentが利用できる機能およびデータの範囲を必要最小限に制限すること。 |
| NFR-024 | ログにAPIキー、パスワード等の秘密情報を出力しないこと。 |
| NFR-025 | 初期リリースは管理者が管理するローカルネットワーク内だけで運用し、センサーデバイス、閲覧画面およびAI質問画面をインターネットへ直接公開しないこと。ローカル通信はHTTPを使用し、外部AIサービスとの通信はHTTPSを使用すること。 |

### 8.4 信頼性・データ品質

| ID | 要件 |
|---|---|
| NFR-030 | 測定日時はUTCで保存・交換し、利用者向けの日時表示および日・時単位の集計境界は`Asia/Tokyo`に固定すること。利用者によるタイムゾーン選択は提供しない。 |
| NFR-031 | データ欠損、異常値または通信途絶を識別できること。 |
| NFR-032 | AI Agentが扱う数値は、保存されたデータまたはシステムが算出した集計結果に基づくこと。 |
| NFR-033 | 障害発生時に原因調査ができるよう、必要な処理結果およびエラーを記録すること。 |

### 8.5 保守性・移植性

| ID | 要件 |
|---|---|
| NFR-040 | データ収集、データ提供およびAI Agentの各機能を独立して変更・保守できること。 |
| NFR-041 | 開発者が同等の実行環境を再現できること。 |
| NFR-042 | データ検証・保存、重複抑止、集計、異常判定、デバイス状態判定およびAI Agentの情報不足時の応答について、自動テストを実施できること。 |
| NFR-043 | 将来センサー種別を追加する際、既存の温度・湿度データとその閲覧機能を維持したまま拡張できること。 |

### 8.6 利用コスト

| ID | 要件 |
|---|---|
| NFR-050 | 開発・運用担当者は、外部AIサービスを利用した質問回数および質問ごとの利用量を確認できること。 |
| NFR-051 | AI Agentの1回の質問で行う処理回数に上限を設定し、その上限を超えて処理しないこと。 |
| NFR-052 | データ収集、保存、通常のデータ確認および入力検証で拒否する質問では、外部AIサービスを呼び出さないこと。 |
| NFR-053 | AI AgentはGemini Developer APIのFree Tierだけを使用し、Free Tierの利用上限到達時に有料枠へ自動切替しないこと。 |

## 9. データ要件

システムは、少なくとも以下の情報を管理する。

| データ分類 | 主な情報 |
|---|---|
| デバイス関連情報 | デバイス識別情報、稼働状態、最終受信日時 |
| 環境測定データ | デバイス識別情報、測定日時、温度、湿度、受信日時 |
| アラート情報 | 対象デバイス、発生日時、種別、判定値、状態 |
| 監視条件 | 温度・湿度の判定条件 |
| AI利用情報 | 質問日時、処理結果、利用状況、エラー情報 |

## 10. 外部インターフェース要件

外部との境界に関する要件を以下に示す。具体的な通信方式、データ形式および画面生成方式は基本設計で定める。

| 接続対象 | 境界に関する要件 | 関連要件 |
|---|---|---|
| センサーデバイス | デバイス識別情報、測定日時、温度および湿度を受け付け、不正なデータを正常データとして扱わないこと | FR-001～005、FR-010～012 |
| 外部AIサービス | 回答生成に必要な情報だけを提供し、サービスを利用できない場合もデータ収集、保存および通常の閲覧へ影響させないこと | FR-041、FR-047～048、NFR-023 |

## 11. 受入条件

以下をすべて満たした場合、初期リリースの要件を満たしたものとする。確認に用いる具体的な試験手順および試験データは、テスト仕様で定める。

| ID | 対応要件 | 受入条件 |
|---|---|---|
| AC-001 | FR-001～005、FR-010～012、NFR-003 | センサーデバイス相当の送信元から温度・湿度を1分間隔で24時間送信し、システムへ到達した正常データが欠損・重複なく保存される。通信失敗後も以降の送信を継続でき、不正な形式・範囲のデータは正常データとして保存されない。 |
| AC-002 | FR-013～016、FR-020～023、FR-060、FR-062 | 利用者が最新値、最終受信日時、指定期間の履歴、日単位の集計、最小値、最大値および平均値を確認でき、閲覧機能とAIチャット間を相互に移動できる。表示値が保存済みデータから求めた期待値と一致する。 |
| AC-003 | FR-030～034、FR-063 | 温度・湿度の閾値超過によりアラートが記録され、同一異常の継続中は重複せず、正常範囲への復帰後の再発は新たに記録される。利用者は履歴を確認できるが、利用者向け画面から監視条件を変更できない。開発・運用担当者は所定の運用手順で監視条件を変更できる。 |
| AC-004 | FR-040～047、FR-061、NFR-032、NFR-050～053 | AIチャットから一問一答で現在値、履歴、統計、期間比較および異常履歴を質問できる。回答には対象期間と主要な根拠値が示され、データがない場合は情報不足と回答する。AI Agentはデータを変更できず、Gemini Developer APIを利用した質問回数と質問ごとの利用量を確認できる。1回の質問で処理回数上限を超えず、入力検証で拒否する質問では外部AIサービスを呼び出さない。Free Tierの上限到達時は安全に失敗し、有料枠へ自動切替しない。 |
| AC-005 | FR-048、NFR-002、NFR-011 | 外部AIサービスを利用できない状態でも、環境データの収集、保存およびAIを使用しない閲覧が継続する。 |
| AC-006 | FR-050～052、NFR-031、NFR-033 | 最終受信日時に応じたデバイスの稼働状態、測定データ受付機能およびデータ保存先の利用可否を確認できる。通信途絶・データ欠損・異常値を識別でき、障害調査に必要な結果とエラーが記録される。 |
| AC-008 | NFR-010 | PostgreSQLの永続volumeを維持した再起動後に、障害前の保存済みデータを確認できる。バックアップからの復元保証は初期リリースの受入対象に含めない。 |
| AC-009 | NFR-020～025、FR-047 | ソースコード、設定履歴およびログに秘密情報が露出せず、未許可の管理操作が拒否され、外部入力が検証される。AI Agentと閲覧機能からデータを登録・変更・削除できず、ローカルサービスへインターネットから直接アクセスできない。 |
| AC-010 | NFR-030 | UTCで保存・交換した測定日時が、`Asia/Tokyo`の期待した日時および日・時境界で表示・集計される。 |
| AC-011 | NFR-040～043 | データ収集、データ提供およびAI Agentを独立して変更できる構成であり、別の開発環境で同等の実行環境を再現できる。定義済みの主要機能の自動テストが成功する。センサー種別を追加しても既存の温度・湿度データと閲覧機能を維持できる設計である。 |

## 12. 用語

| 用語 | 説明 |
|---|---|
| センサーデバイス | 温度・湿度の環境情報を取得し、システムへ送信する機器 |
| AI Agent | 質問内容を判断し、許可された範囲の情報を利用して回答を生成するAI機能 |
| 外部AIサービス | 初期リリースではGemini Developer APIのFree Tierを指す |
