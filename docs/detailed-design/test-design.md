# SoraSense 詳細設計書 — テスト設計

## 2. 基本方針

各テストは要件ID、設計文書、前提、入力、操作、期待結果を持つ。時刻依存処理はClockを注入して固定し、外部AIは単体・通常結合テストでFakeを使用する。E2Eの外部AI実試験は利用量上限を設けて分離する。DB結合テストはPostgreSQL 16を使用し、SQLiteで代替しない。

## 6. 性能テスト

- 1分間隔24時間相当の1,440件を欠損・重複なく登録する。
- 30日分43,200件を投入し、最新値、履歴、日集計を各100回測定する。
- 100回中95回以上で3秒以内に表示開始相当のAPI・クエリ応答を得る。
- 測定登録とGrafana照会を並行し、収集が継続することを確認する。
- 性能結果には環境、データ件数、同時実行数、p50、p95、最大値を記録する。

### 7.1 フェーズ6詳細ケース

各ケースは固定Clock、決定的なToken Generator、Fake認証器またはFake Agent境界を注入して再現可能にする。HTTPケースではCookie jarを分離し、別ブラウザ相当のセッションを混在させない。

| ID | 前提・操作 | 期待結果 | 対応 |
|---|---|---|---|
| P6-001 | 認証情報を正しくPOST `/login`へ送る | 303、`/agent`遷移、新規セッションCookie、既存IDを不使用 | UT-SEC-001、ST-003 |
| P6-002 | 利用者名またはパスワードを誤る | 403、同一の一般メッセージ、入力・秘密値を再表示・ログ出力しない | UT-SEC-002、ST-007 |
| P6-003 | 同一IPまたは同一利用者名で5回失敗後、6回目を送る | 6回目は429、`Retry-After`あり、パスワード検証なし | UT-SEC-003、ST-008 |
| P6-004 | 制限時間経過後に正常ログインする | 制限解除、303、該当する両キーの失敗履歴消去 | UT-SEC-003、ST-008 |
| P6-005 | Cookieなし・未知・ログアウト済みでGET `/agent` | `/login?reason=session_expired`へ303、無効Cookie削除 | UT-SEC-001、ST-003 |
| P6-006 | 最終利用から1800秒未満・ちょうど1800秒・超過でアクセス | 未満だけ有効、境界以上は失効 | UT-SEC-001、ST-003 |
| P6-007 | 生成から28800秒未満・ちょうど28800秒・超過でアクセス | 未満だけ有効、境界以上は失効 | UT-SEC-001、ST-003 |
| P6-008 | 認証済み状態で再ログインする | 旧セッション削除、新規ID発行、旧IDの再利用拒否 | UT-SEC-001、ST-003 |
| P6-009 | CSRFを一致・欠落・不一致・別セッション値で状態変更POSTする | 一致だけ実行、その他は403で副作用なし | UT-SEC-001、ST-003 |
| P6-010 | 質問フォームトークンを初回・再利用・期限後に送る | 初回だけ処理、再利用・期限後は409、Agent呼出しなし | UT-SEC-001、ST-003 |
| P6-011 | 6個のフォームトークンを順次発行する | 最新5件だけ有効、最古は409 | UT-SEC-001 |
| P6-012 | 正常質問、空白だけ、2000/2001文字を送る | 正常と2000文字だけ境界通過、不正時Agent呼出しなし | UT-WEB-001、ST-002 |
| P6-013 | 不正Content-Type、非UTF-8、4096/4097バイト本文を送る | 正常境界だけ受付、順に415・400・413、Agent呼出しなし | UT-WEB-001、ST-002 |
| P6-014 | 質問・回答・reasonへHTMLとスクリプト断片を含める | HTMLとして実行されず、任意reasonは表示されない | ST-002 |
| P6-015 | AI画面の成功・リダイレクト・4xx・5xxを取得する | 定義済みセキュリティヘッダーと`Cache-Control: no-store`を付与 | ST-004 |
| P6-016 | ローカルHTTP運用でCookieを取得する | `Secure`なし、`HttpOnly`、`SameSite=Lax`、`Path=/`、Domainなし | ST-004 |
| P6-017 | CSRF付きPOST `/logout`後に旧Cookieでアクセスする | セッション削除、Cookie削除、旧Cookie再利用拒否 | UT-SEC-001、ST-003 |
| P6-018 | ローカル運用でWeb認証未設定または片側だけ設定して起動する | すべて設定エラー。開発・テストで両方未設定ならWeb経路なし | ST-007 |
| P6-019 | 任意`X-Forwarded-For`を直接送ってログイン失敗を繰り返す | ヘッダーで制限キーを回避できず、直接接続元IPを使用 | ST-008 |
| P6-020 | 内部例外を発生させる | 500とrequest_idだけを表示し、例外本文・質問・秘密値を応答とログへ出さない | ST-002、ST-007 |

## 8. 障害・復旧テスト

PostgreSQL、FastAPI、Grafana、Gemini Developer APIを個別に停止し、他機能への影響範囲が基本設計どおり分離されることを確認する。Geminiでは接続不能、401、429および5xxをFakeで再現し、429時に有料枠へ切り替わらないことを確認する。PostgreSQL停止では保存済みvolumeを維持して再起動し、データ保持を確認する。バックアップを隔離DBへ復元し、テーブル、VIEW、権限、最新値を照合してRPO・RTOを記録する。
