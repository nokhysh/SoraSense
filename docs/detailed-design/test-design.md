## 2. 基本方針

各テストは要件ID、設計文書、前提、入力、操作、期待結果を持つ。時刻依存処理はClockを注入して固定し、外部AIは単体・通常結合テストでFakeを使用する。E2Eの外部AI実試験は利用量上限を設けて分離する。DB結合テストはPostgreSQL 16を使用し、SQLiteで代替しない。

## 4. DB・API結合テスト

| IT-005 | 異常開始・継続・復帰・再発 | OPEN重複なし、履歴2件 |
| IT-006 | Grafanaユーザー権限 | VIEW SELECT成功、基底表SELECT/UPDATE失敗 |

| IT-008 | OpenAI停止 | Agentはエラー、測定登録とGrafana照会は成功 |

## 6. 性能テスト

- 1分間隔24時間相当の1,440件を欠損・重複なく登録する。
- 30日分43,200件を投入し、最新値、履歴、日集計を各100回測定する。
- 100回中95回以上で3秒以内に表示開始相当のAPI・クエリ応答を得る。
- 測定登録とGrafana照会を並行し、収集が継続することを確認する。
- 性能結果には環境、データ件数、同時実行数、p50、p95、最大値を記録する。

## 7. セキュリティテスト

| ID | 確認内容 |
|---|---|
| ST-001 | APIキーなし・不正・別デバイスIDを拒否する |
| ST-002 | SQLインジェクション、XSS、過大本文、不正Content-Typeを拒否・無害化する |
| ST-003 | CSRFなし・不一致、失効Session、固定Sessionを拒否する |
| ST-004 | Cookie属性とセキュリティヘッダーが設定される |
| ST-005 | Grafana匿名アクセスと基底テーブル操作を拒否する |
| ST-006 | Agentから更新、任意SQL、任意URLを実行できない |
| ST-007 | ソース、設定履歴、API応答、ログにSecretがない |
| ST-008 | ログイン・APIレート制限が上限で作動する |

## 8. 障害・復旧テスト

PostgreSQL、FastAPI、Grafana、OpenAI APIを個別に停止し、他機能への影響範囲が基本設計どおり分離されることを確認する。PostgreSQL停止では保存済みvolumeを維持して再起動し、データ保持を確認する。バックアップを隔離DBへ復元し、テーブル、VIEW、権限、最新値を照合してRPO・RTOを記録する。

| AC-005 | IT-008、障害テスト | AI停止中も収集・保存・Grafana閲覧が成功 |
| AC-006 | UT-STA-001、UT-GAP-001、IT-004/009/010、ログ確認 | 未受信を含む状態・ヘルス・通信途絶・測定欠損を識別し調査可能 |
| AC-007 | 性能テスト | 100回中95回以上が3秒以内 |
| AC-008 | IT-004、復旧テスト | 保存済みデータ保持、日次バックアップ、RPO/RTO達成 |
| AC-009 | ST-001～008 | 未許可操作拒否、入力検証、Secret非露出、参照専用 |
| AC-010 | UT-QRY-001、E2E-001 | UTC保存と`Asia/Tokyo`表示・集計境界が期待値一致 |
| AC-011 | IT-007、E2E-005、全自動テスト | 責務分離、環境再現、主要自動テスト成功、既存データ契約維持 |
